Общение с администрацией

Модуль работает поверх scanner. Он берёт события VK, где найдено исходящее сообщение админа, определяет источник клиента по истории openrouter.db и выполняет нужное действие.

Правила

  • source=senler — добавить VK ID в Senler список 3748755 через subscribers/add.
  • source=salebot — добавить Salebot client_id в список 2427562 через add_to_list.
  • Если источник не найден в OpenRouter, модуль дополнительно проверяет VK ID через Salebot find_client_id_by_platform_id и берёт id из ответа как Salebot client_id.
  • Каждое новое сообщение админа продлевает участие на 7 дней. После истечения срока модуль удаляет человека из этого же списка через subscribers/del или remove_from_list.
  • Если источник не найден, событие записывается как skipped, чтобы модуль не дёргал API вслепую.

Повторная обработка защищена уникальным scanner_event_id. Активные участия хранятся отдельно в таблице memberships, чтобы срок можно было продлевать и безопасно удалять просроченных.

ENV

ADMIN_HANDOFF_ENABLED=1
ADMIN_HANDOFF_PROCESS_EXISTING=0
ADMIN_HANDOFF_RETENTION_DAYS=7
ADMIN_HANDOFF_SALEBOT_LOOKUP_FALLBACK=1
ADMIN_HANDOFF_SENLER_SUBSCRIPTION_ID=3748755
ADMIN_HANDOFF_SALEBOT_LIST_ID=2427562
SENLER_ACCESS_TOKEN=...
SENLER_GROUP_ID=...
SALEBOT_API_KEY=...

ADMIN_HANDOFF_SCANNER_DB_PATH и ADMIN_HANDOFF_OPENROUTER_DB_PATH нужны только если автоопределение путей не подходит. Для поиска Salebot client_id по VK/platform ID можно указать SALEBOT_GROUP_ID.

API

GET /nexus/admin-handoff/api/env-status
GET /nexus/admin-handoff/api/actions?limit=100
GET /nexus/admin-handoff/api/memberships?status=active
POST /nexus/admin-handoff/api/process
POST /nexus/admin-handoff/api/actions/{id}/retry
