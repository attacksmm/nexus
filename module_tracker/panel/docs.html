Трекер

Модуль собирает визиты, UTM, click id, IP/Geo, устройство и подтвержденные формы. Скрипт не меняет страницу: не правит URL, DOM, стили, формы и не блокирует отправку.

Tilda: один автономный код в Head

  1. Оставьте отдельные блоки Яндекс.Метрики, Mail.ru, VK, Senler и других счетчиков в Head.
  2. Удалите только старый тег Nexus. Во вкладке «Скрипт» включите «свой баннер · без блоков Tilda», скопируйте новый snippet и поставьте его самым первым кодом глобального Head — перед всеми счетчиками.
  3. Удалите только аналитические noscript-пиксели. JavaScript не может остановить их при отключенном JavaScript, когда запросить согласие невозможно.
  4. Сохраните настройки и выполните «Опубликовать все страницы». Добавлять T972 или любой другой блок на страницы не нужно.

Плашка и настройки встроены прямо в скопированный Head-код, поэтому они показываются даже при блокировке домена junior.sobakovod.pro. Gate не содержит код сторонних метрик. Он перехватывает их известные внешние файлы, изображения, fetch/XHR/beacon, таймеры и записи cookie/storage до выбора. После решения плавающая кнопка не показывается; обычная ссылка href="#cookie-settings" в подвале или политике открывает выбор повторно.

Защита от случайной ранней загрузки

data-consent="managed" запрещает Nexus Tracker создавать visitor/visit cookie, localStorage и сетевые события до разрешения аналитики. Gate также удерживает известные URL Метрики, Mail.ru, Nexus, Senler, Tilda Stat и рекламных пикселей. Новые сторонние скрипты всё равно нужно явно относить к analytics, advertising или custom: назначение произвольного будущего кода нельзя определить безошибочно.

data-site нужен только для группировки сайтов в панели. После согласия скрипт читает first-party _ym_uid, если его уже поставила Метрика.

Как разметить новый скрипт

Inline-код храните как type="text/plain", а внешний URL — в data-src. Gate сам превратит его в исполняемый скрипт после разрешения категории:

<script type="text/plain" data-nexus-consent="analytics">
  // код аналитики
</script>

<script type="text/plain" data-src="https://example.test/pixel.js"
  data-nexus-consent="advertising"></script>

Не добавляйте аналитические noscript img: без JavaScript запрос согласия не работает, поэтому такой пиксель нарушит принцип «сначала выбор — потом загрузка». Не используйте автоматическое согласие по скроллу или продолжению просмотра.

Диагностика UTM

Вкладка UTM показывает, почему в источниках много (none): события без utm_source, страницы без разметки, click id без source и вероятные перестановки UTM-полей. Колонка «Оригинал» всегда показывает фактические значения, которые пришли в событии.

Поиск профилей

Поиск во вкладке «Люди» проверяет контакты, имя, visit/visitor id, IP, GeoIP город/страну, browser/device, fingerprint, host/referrer/URL, все UTM-поля, внешние id вроде _ym_uid/yclid и сохраненные значения форм/сырых событий.

Подтверждение формы

Автоматически срабатывают success URL и видимые success-блоки Tilda/GetCourse-подобных форм. Для SPA можно вызвать:

window.NexusTracker.confirmForm(document.querySelector("form"), { confirmation_reason: "crm_success" });

Хранение

Raw-события чистятся вручную во вкладке «Настройки» по retention, по умолчанию 6 месяцев. Склеенные профили людей остаются в БД модуля и синхронизируются в customer-db таблицу visitor_profiles.
