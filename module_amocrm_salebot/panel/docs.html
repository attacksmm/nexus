amoCRM → SaleBot

Модуль принимает webhook amoCRM при создании или изменении сделки. Если поле utm_term содержит подтверждённый salebot_id, модуль записывает переменные клиенту SaleBot и вызывает callback callback_amoCRM.

Что отправляется

  • amo_deal_info — читаемая сводка сделки.
  • amo_deal_id, amo_deal_name, amo_price, amo_responsible, amo_pipeline, amo_status, даты, компания и контакты.
  • Каждое заполненное поле сделки — как amo_{field_code}; если кода нет, используется нормализованное название поля.

Сначала вызывается SaleBot save_variables, только после успешной записи — callback.

Безопасное определение SaleBot ID

В строгом режиме числовое значение само по себе не считается SaleBot ID. Модуль требует подтверждение источника в истории OpenRouter или явном поле salebot_id Customer DB. Это защищает от отправки VK/Senler ID в SaleBot.

Успешный get_variables сам по себе не является строгим доказательством: VK ID может совпасть с существующим client ID другого клиента SaleBot. Поэтому режим «Nexus или SaleBot API» и полное доверие utm_term включаются только явно.

Дедупликация и ошибки

Несколько webhook одного изменения объединяются по снимку сделки. Если набор переменных и callback не изменился, повторная отправка получает статус deduped. Сетевые и API-ошибки повторяются до пяти раз с увеличивающейся задержкой. После перезапуска Nexus очередь продолжается из SQLite.

Подключение

  1. Проверьте готовность ENV в панели.
  2. Оставьте строгую проверку ID и сохраните настройки.
  3. Введите тестовую сделку во вкладке «Проверка сделки» и выполните предпросмотр.
  4. Включите модуль и нажмите «Зарегистрировать в amoCRM» либо добавьте показанный URL вручную.

Webhook

POST https://junior.sobakovod.pro/nexus/amocrm-salebot/api/webhook?secret=...

Поддерживаются события amoCRM add_lead, update_lead, status_lead и responsible_lead. Endpoint всегда отвечает amoCRM кодом HTTP 200, а реальный результат виден в журнале модуля.
