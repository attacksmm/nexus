Конверсии

Модуль показывает четыре дневных графика и сквозную воронку клиента. Он читает базы Nexus и официальный Export API GetCourse, не изменяя заказы, клиентов, сделки или события других модулей.

Четыре графика

ГрафикИсточник и смысл
ЗаработаноТочное поле Заработано из экспорта GetCourse: платёж за вычетом комиссии платёжной системы, налога и других комиссий.
Оплаченоpayed_money из заказа — сумма платежа до комиссий.
ЗаказыКоличество заказов по выбранным статусам, товару и UTM.
Новые клиенты VK / TelegramУникальные platform_id из таблиц клиентов VK и Telegram по дате первого контакта, а при её отсутствии — по дате создания записи. Рекламный utm_source не определяет канал мессенджера.

Линию можно заменить столбцами или областью. Периоды: 7 дней, 30 дней, 365 дней или произвольные даты. День заканчивается по часовому поясу Europe/Moscow.

Почему «Заработано» не вычисляется процентом

Ставка зависит от способа оплаты, банка, срока рассрочки, налога и дополнительных комиссий. В webhook GetCourse этих итоговых полей нет. Поэтому модуль малолимитно синхронизирует официальный экспорт и хранит в своей БД только финансовый агрегат заказа.

Если точное значение ещё не пришло, заказ отмечается как ожидающий синхронизации и не включается в сумму «Заработано». Приблизительная комиссия никогда не подставляется.

Начальная синхронизация загружает 365 дней, затем обновляет последние 31 день раз в три часа. Лимит модуля — 15 запросов Export API за два часа. Ручной запуск находится в шестерёнке.

Как связываются клиенты

Для сквозной аналитики строится дисковый индекс связей. Записи объединяются только по строгим идентификаторам:

  • нормализованный телефон и email;
  • salebot_id между Avito, VK, Telegram и amoCRM;
  • VK/Senler platform_id, включая его копии в vk_id и utm_term GetCourse/amoCRM — только если значение существует в справочнике VK-клиентов;
  • ym_uid, Bizon user ID и идентификаторы Tracker, когда они присутствуют в обоих сервисах.

Имя, город, IP и похожие признаки не используются. Индекс хранится в data/funnel-cache.db и обновляется в фоне не чаще раза в 15 минут. Строгие идентификаторы записываются только как необратимые 128-битные хеши. Панель читает с диска только выбранный период, а не всю базу в RAM. Процент «связано между сервисами» показывает долю клиентов, у которых найдены записи хотя бы в двух системах.

Два режима воронки

РежимКак считается
КоличествоКаждый этап отбирается по дате собственного события внутри выбранного периода. Продажа — по дате оплаты; основное число содержит уникальных покупателей полных тарифов GetCourse, а подпись отдельно показывает покупателей и заказы GetCourse. Этот режим нужен для сверки с GetCourse.
СквознаяПериод выбирает когорту по дате первого касания. Следующий этап считается только при наличии всех предыдущих связей. Этот режим показывает конверсии пути, а не количество оплат за выбранные даты.

Фильтр «Оплачены / Частично / Не оплачены» применяется к продажам в обоих режимах. Для неполного исторического покрытия интерфейс показывает фактическое окно Bizon; отсутствие истории нельзя трактовать как реальный отвал.

Этапы

ЭтапПравило
Источник / касаниеУникальный клиент с самым ранним известным источником. Источником считается только Avito или фактический utm_source; технические названия amoCRM, GetCourse и Bizon источниками не становятся.
Регистрация в мессенджереСвязанная запись клиента только в VK или Telegram. Avito считается источником, а события Tracker — касаниями и атрибуцией; в регистрации они не входят.
В эфиреСвязанная запись посещения Bizon. Дата берётся прежде всего из date_web, затем из webinar_date, webinar_at либо даты внутри webinarId. Даты создания и обновления строки не используются.
Заявка / заказУникальный клиент с заказом GetCourse или сделкой только из воронки amoCRM «1. Входящая». Несколько заказов одного человека считаются один раз; исходящие и прочие воронки amoCRM полностью исключены.
ПродажаОплаченный или частично оплаченный заказ полного тарифа основного курса GetCourse. Мини-курсы, доплаты, отдельные модули и технические заказы исключаются. Входящая amoCRM связывает путь и подтверждает заявку, но без тарифа GetCourse самостоятельно продажу не создаёт.

Этапы идут в бизнес-порядке «Источник → Регистрации → Эфиры → Заявки → Продажи». В каждом блоке остаются только название и число. Над стрелкой перехода показана доля следующего этапа от всех касаний, под стрелкой — отношение к предыдущему числу. В таблице у касаний показана доля от общего трафика, у остальных чисел — доля от касаний соответствующего источника.

В количественном режиме числа остаются независимыми событиями выбранного периода, поэтому процент под стрелкой является арифметическим отношением соседних значений, а не доказательством связанного перехода конкретных людей. Строгий клиентский путь показывает режим «Сквозная». Число заказов GetCourse выводится отдельно, поэтому повторные заказы одного покупателя не теряются.

Верхнее число продаж — уникальные покупатели полного тарифа. Технический показатель под воронкой показывает количество тарифных заказов: если один человек купил два разных тарифа, сверху он считается один раз, а в заказах — два раза. Продажи вне полной цепочки показываются отдельно и не искажают конверсию основной воронки. Сегменты «ИИ» и «База» в API считают долю всех атрибутированных продаж, чей первый utm_source содержит отдельный маркер _ai или _baza.

Подключение

В стандартной установке пути находятся автоматически. Для нестандартного расположения доступны:

GETCOURSE_REVENUE_CUSTOMER_DB_PATH=/absolute/path/customer-db.db
GETCOURSE_REVENUE_ORDERS_DB_PATH=/absolute/path/getcourse-orders.db
GETCOURSE_REVENUE_TRACKER_DB_PATH=/absolute/path/tracker.db
GETCOURSE_ACCOUNT_NAME=sobakovod
GETCOURSE_API_TOKEN=***

API и приватность

Панель использует защищённые endpoints POST /nexus/getcourse-revenue/api/analytics, GET /sync-status и POST /sync. Ответ содержит только агрегаты, статусы качества и варианты UTM-фильтров — без имён, телефонов, email и raw webhook.
