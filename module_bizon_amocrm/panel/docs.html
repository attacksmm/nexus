Конструктор Bizon365 → amoCRM

Модуль читает нормализованные посещения из bizon-reports, выбирает связку вебинара, проверяет порог просмотра и ищет сделки по точному телефону/email. Поиск проверяет amoCRM и локальный снимок amo_deals в Customer DB, поэтому видит сделки даже у раздельных дублирующихся контактов. Если сделка найдена, дополняется самая свежая активная; новая создаётся только когда у человека вообще нет сделок.

Связка

  1. Для одного webhook во всех комнатах выберите «Все комнаты» — значение комнаты вводить не требуется.
  2. Укажите комнату, точный webinarId, фрагмент текста или регулярное выражение.
  3. Задайте диапазон просмотра. Минимум включается, максимум не включается: диапазоны 0–<60 и от 60 однозначно разделяют участников ровно на 60-й минуте.
  4. Выберите целевую воронку и статус новой сделки.
  5. Отметьте воронки и, при необходимости, статусы поиска дублей.
  6. Настройте порядок проверки полей: обычно телефон, затем email.
  7. Выберите активных сотрудников для round-robin.

Название новой сделки

Шаблон по умолчанию: {webinar_date} | {webinar_time} | {watch_minutes_round}м | {username}. Дата и время рассчитываются в часовом поясе Europe/Moscow. Шаблон используется только для новой сделки; название найденного дубля не меняется.

Сопоставление полей

Каждая строка конструктора описывает перенос поле Bizon → сущность amoCRM → поле amoCRM. Поддерживаются пользовательские поля сделки, пользовательские поля контакта, название сделки и имя контакта.

watch_minutes_round передаёт целое число минут. source_user_id берёт устойчивый ID участника Bizon: сначала chatUserId, затем uid, sid или person_key. Источник _ym_uid ищет значение последовательно в _ym_uid, ym_uid, param1 и p1.

Вычисляемые источники messenger_type, dialog_salebot_url и dialog_vk_url используют исходный utm_term и ищут его точное совпадение в таблицах Telegram/VK модуля Customer DB. SaleBot-ссылка формируется только для Telegram, VK-ссылка — только для ВКонтакте. Если ID отсутствует или найден сразу в обеих таблицах, обе ссылки остаются пустыми.

Примечание поддерживает настоящие многострочные шаблоны. Строки, у которых отсутствуют все значения, автоматически не добавляются; для времени входа и выхода доступны {view_from_text} и {view_till_text}.

Полный отчёт Bizon передаёт chat_message_count и chat_messages_text — реплики участника с таймкодами. Bizon не маркирует отдельно обычные комментарии и ответы на вопросы ИИ, поэтому они выводятся единым блоком «Сообщения и ответы в чате».

Типы приводятся автоматически: числа — в numeric, логические значения — в checkbox, дата вебинара — в Unix timestamp для date/date_time. Массивы и объекты сериализуются в JSON при записи в текстовое поле.

При создании новой сделки контакт формируется вместе с ней. При найденной сделке модуль заполняет только пустые сопоставленные поля сделки и пустые поля её основного контакта. Уже занятые значения никогда не переписываются.

Каталоги

Вкладка «Каталоги» показывает все доступные воронки и статусы amoCRM, все пользовательские поля сделок и контактов, а также полный известный набор полей Bizon. Новые ключи, появившиеся в реальном attendance-feed, автоматически добавляются в каталог без показа персональных значений.

Дубли и round-robin

Правила выполняются по точному нормализованному телефону/email без ограничения по воронке или статусу, включая успешные, закрытые и upsell. Если контакты продублированы в amoCRM, локальная таблица amo_deals объединяет их для поиска по одной личности.

Выбирается самая свежая активная сделка; если активных нет — самая свежая из закрытых. В неё добавляется идемпотентное примечание и только отсутствующие сопоставленные поля. Цена, название, воронка, статус, ответственный, теги и заполненные поля не меняются.

Ответственный найденного дубля никогда не меняется. Round-robin применяется исключительно к новой сделке. Связки с одинаковым выбранным набором сотрудников используют общую очередь, поэтому ветки <60 и ≥60 распределяются совместно. Курсор сдвигается только после успешного создания; неактивные сотрудники amoCRM исключаются.

Внутренний feed

http://127.0.0.1:8080/bizon-reports/api/attendance-feed — внутренний адрес между модулями на сервере Nexus. Это не публичный webhook и его не нужно вставлять в Bizon. Готовый webhook находится в панели модуля «Bizon365 отчёты».

Безопасное включение

  1. Создайте точную связку тестовой комнаты.
  2. Оставьте dry-run включённым и проверьте журнал.
  3. Используйте уникальный тестовый телефон/email.
  4. Только затем отключите dry-run.
AMO_BASE_URL=https://sobakovodpro.amocrm.ru
