Модуль «Рассылки»

Отправляет сообщения VK и Telegram по сохранённым сегментам из разрешённых листов «Базы клиентов» и ручных получателей.

Настройка

  1. На вкладке «Настройки» добавьте VK и Telegram bot token. Значения сохраняются в ENV Nexus и не возвращаются в браузер. Если хост не имеет прямого доступа к api.telegram.org, задайте HTTP/SOCKS proxy в SBKVD_LETTER_TELEGRAM_PROXY_URL или закрытый proxy/base URL в SBKVD_LETTER_TELEGRAM_API_BASE. MTProto proxy-ссылки t.me/proxy для Bot API не подходят.
  2. Разрешите листы, выберите канал и поле с ID получателя.
  3. На вкладке «Сегменты» создайте аудиторию по последовательным блокам: источники, условия, корректировки и итог. До 10 000 получателей можно импортировать из CSV/TXT. Для экспорта SaleBot используются колонки Мессенджер и Идентификатор внутри мессенджера; также распознаются channel/platform и platform_id/recipient_id/id. Для файла только с ID выберите канал перед импортом.
  4. На вкладке «Шаблоны» загрузите вложения и соберите общую VK/Telegram-клавиатуру из рядов и кнопок. Кнопки можно переносить drag-and-drop; тот же state доступен в универсальном JSON.
  5. На вкладке «Рассылка» выберите один или несколько готовых сегментов, текст, вложения и кнопки.

HTML и MarkdownV2 применяются только в Telegram. При отправке того же шаблона в VK модуль автоматически убирает теги и служебные символы разметки, сохраняя читаемый текст и переносы строк.

Поле запуска по расписанию всегда принимает московское время (МСК, UTC+3). В базе время хранится в UTC, поэтому часовой пояс самого сервера не влияет на момент запуска. Запланированная рассылка сохраняется в SQLite и переживает перезапуск Nexus; если сервис недоступен в заданный момент, отправка начнётся после его восстановления.

Управление рассылкой

VK и Telegram обрабатываются независимыми параллельными очередями; медленный канал не задерживает второй. Указанная скорость — верхний потолок. Адаптивный регулятор стартует с него, при ответе о превышении лимита ставит на короткую паузу только затронутый канал и снижает его скорость, а затем постепенно разгоняет обратно при успешной отправке. Telegram retry_after соблюдается точно; одновременные ошибки одного всплеска считаются одним событием. Настройка «Параллельность на канал» применяется отдельно к каждому сервису. Активную рассылку можно поставить на паузу и продолжить. Уже принятый API запрос может успеть завершиться, остальные получатели останутся в очереди. После завершения или отмены кнопка «Доотправить неотправленные» снова ставит в очередь ожидающих и пропущенных получателей без сохранённого факта отправки; отправленные, получатели с ошибкой, stop-list и not_allow исключаются. Ошибочные строки сохраняются для отдельного явного повтора и не доотправляются этой кнопкой автоматически, поскольку после аварийного перезапуска результат запроса к API может быть неизвестен и повтор создал бы дубль.

Отказ пользователя от сообщений не считается ошибкой: получатель получает статус not_allowed и сохраняется в отдельном списке not_allow по каналу. Настройки позволяют просмотреть этот список и вручную вернуть получателя. Остальные ошибки API и сети сохраняются в истории для диагностики и отдельного явного повтора.

После остановки рассылки можно удалить сохранённые сообщения: VK удаляется пакетами с флагом удаления для всех, Telegram — по сохранённым ID. Модуль отмечает удалёнными только сообщения, удаление которых подтвердил API.

Вкладка «Удаление» считает и удаляет сообщения по точному содержанию или уникальному фрагменту. Она ищет среди сообщений, сохранённых модулем, а также в исходящей истории VK. Telegram Bot API не даёт глобального поиска истории, поэтому Telegram-сообщения доступны здесь только при наличии сохранённого внешнего ID. Во время удаления число оставшихся сообщений и красная полоса прогресса уменьшаются.

В «Настройках» можно вручную добавить VK или Telegram platform_id в игнор список. По умолчанию такие получатели исключаются из запуска и безопасной доотправки; для отдельной кампании исключение можно отключить соответствующей галочкой.

Перед запуском доступны три включённых по умолчанию исключения: «Купившие», «Игнор список» и «Запретившие». Итоговый предпросмотр показывает количество исключённых по каждой причине. Галочку можно снять для конкретной кампании; выбор фиксируется в snapshot и соблюдается при доотправке. Если «Запретившие» отключены, успешная повторная доставка удаляет устаревшую запись not_allow, а новый отказ пользователя снова её создаёт или обновляет.

Кнопка «Обновить купивших» в настройках пересобирает локальный список по заказам GetCourse с фактической оплатой или состоянием paid/partial и по сохранённым идентификаторам из импортированных сделок. Числовой utm_term связывается с VK platform_id, а для Telegram — с platform_id либо SaleBot salebot_id. Заказы без однозначной связи не исключаются.

Хранение

Шаблоны и вложения находятся в системной папке sbkvd-letter Файлового хранилища. Кампании, snapshot сегментов, получатели, попытки, not_allow и внешние ID сообщений находятся в SQLite модуля. Пути SBKVD_LETTER_CUSTOMER_DB_PATH и SBKVD_LETTER_FILE_STORAGE_DB_PATH нужны только как необязательный override; внутри Nexus модуль находит эти БД автоматически.

Надёжность

При запуске backend загружает выбранные сегменты по ID, объединяет аудиторию без дублей и фиксирует snapshot. Изменение сегмента не меняет уже созданную рассылку. Универсальная клавиатура компилируется в нативные форматы VK и Telegram непосредственно перед отправкой. Сетевые ошибки API/proxy повторяются отдельным длинным backoff; при серии сетевых ошибок кампания автоматически ставится на паузу, чтобы не прожечь большой сегмент.

Все изменения SQLite внутри модуля проходят через единую очередь коротких транзакций. Результаты параллельных доставок объединяются в пакетные транзакции, а проверки перед отправкой используют параллельные WAL-чтения. Поэтому служебные записи не конкурируют за единственный writer SQLite и не образуют очередь отдельных commit на каждого получателя: при занятой базе пакет ждёт освобождения и повторяется, не переводя кампанию в ошибку и не отключая функции истории, исключений, удаления или учёта доставок.

После запуска или продолжения статус сначала отображается как «Подготовка». Он меняется на «Отправляется» только после первой новой подтверждённой доставки; счётчик и heartbeat кампании обновляются в той же пакетной транзакции, что и результат отправки.

Большие аудитории сохраняются пакетами, поэтому подготовка не блокирует worker. Для сообщений без переменных текст хранится один раз в snapshot кампании, а не дублируется в каждой строке получателя. Прогресс пересчитывается с ограниченной частотой, чтобы история не замедляла отправку.

Права

Viewer просматривает данные, editor управляет шаблонами, сегментами, рассылками и not_allow, admin дополнительно настраивает листы, токены и удаляет историю.
